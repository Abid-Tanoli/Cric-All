## Part C — Focused code review

No code was changed. Severity reflects impact if the path is exercised.

### High

**F-01 — `applyPlayerNames.js:313-317`: merging one player overwrites every listed reference field, even fields pointing at other players.**

```js
const filter = { $or: fields.map((field) => ({ [field]: playerId })) };
const update = { $set: Object.fromEntries(fields.map((field) => [field, targetId])) };
await model.updateMany(filter, update);
```

If a `Delivery` matches on `fielderId`, the same update also sets `batsmanId`, `bowlerId`, and `nonStrikerId` to the target player. `Ball` and `Partnership` have the same problem. A single merge can therefore corrupt unrelated scorecard rows.

**Fix:** rewrite only the fields that actually match. Use one `bulkWrite` operation per field, or an aggregation-pipeline update with `$cond` per field. Add a regression test with a delivery where only the fielder matches and assert the other three fields are unchanged.

### Medium

**F-02 — `orgHandoverController.js:119-247`: handover is a multi-write operation with no transaction or rollback.**

The controller creates/saves the user, upserts membership, demotes the previous owner, saves `org.owner`, and writes the audit entry as separate writes. A failure after a partial step can leave the new owner without the organization, the old owner already demoted, or the audit missing.

**Fix:** run the writes in a Mongo session transaction where the deployment supports replica sets; otherwise add explicit compensating rollback and make the operation idempotent. Keep “promote before demote” ordering.

**F-03 — `matchController.js:1438-1490`: `setSquad15` accepts arbitrary player IDs.**

It checks count (11–20), captain/vice-captain presence, at least one wicket-keeper, and that the team belongs to the match. It does not check that player IDs are unique, belong to the team, or that captain/vice-captain/wicket-keepers are members of `players`.

**Fix:** validate every ID as an ObjectId, dedupe, load the team roster/squad, require all IDs to be members, and require the role IDs to be a subset of `players`.

**F-04 — `matchController.js:1757-1791`: `setBowlingXI` does not verify the Playing XI.**

Only count and match membership are checked. A caller can submit players outside the XI, duplicates, or IDs from the other team.

**Fix:** require the submitted IDs to be a unique subset of that team’s `playingXI`.

**F-05 — `matchController.js:1817-1870`: `setTeamRoles` does not verify squad membership.**

Captain, vice-captain and wicket-keepers can be any player IDs.

**Fix:** require them to belong to the team’s squad (and, where the rule is “roles from XI”, to the Playing XI).

**F-06 — `matchController.js:1271-1276` and `1558-1564`: squad checks are skipped when the resolved squad is empty.**

`if (squad.players.length > 0 && ...)` means a team with no squad accepts any player ID. The same pattern appears in `setTwelfthMan`.

**Fix:** treat “no squad” as an error for these setup endpoints, or validate against the team roster instead of silently skipping.

**F-07 — `applyPlayerNames.js:424-497`: player merge is non-transactional and not resumable.**

`mergePlayerStats` runs before reference updates; the audit entry is written only at the end. A crash after stats merge but before deletion can double-count on a retry, and partial references remain.

**Fix:** wrap the merge in a transaction, or write a checkpoint/idempotency key and make each step safe to repeat. Write the audit entry with the change, not only after all changes succeed.

**F-08 — Cleanup misses known reference shapes.**

`playerNameCleanup.js`/`applyPlayerNames.js` do not rewrite:

- `Blog.relatedId` when `relatedType` is `"Player"`;
- `CommunityPost.subject.ref` when `subject.type` is `"player"`;
- legacy top-level `Match.batsmanOnStrike`, `batsmanNonStrike`, and `bowler`.

`hasUnresolvedReferences` prevents deletion when one of these remains, so the merge silently leaves a placeholder behind. The report tooling also has no runbook.

**Fix:** add the fields to the reference map and tests. Document the review → dry-run → apply procedure, including how to handle “placeholder retained”.

**F-09 — `backupDb.js:65-69`: Docker backup has no Mongo authentication.**

The docker branch runs `mongodump --db ...` without `--username`, `--password`, or `--authenticationDatabase`. With Mongo auth enabled (normal for the VPS), this fails and the script falls back to host `mongodump`, contradicting the README’s “no host tools required”. The failure is only visible from the combined error message.

**Fix:** pass credentials from environment into the container invocation, or document that host `mongodump` is a hard requirement for authenticated deployments. Never print the credentials.

**F-10 — `TournamentController.js:136-214`: list pagination is applied after loading everything.**

`getTournaments` loads all tournaments and all linked matches, derives status in memory, then slices by `page`/`limit`. That is correct for the current data size but scales poorly and holds a large result set per request. `getSeries` has no pagination at all.

**Fix:** move filtering/pagination into the database where possible, or cache the derived board. Keep the derived-status behavior covered by the existing tests.

### Low

**F-11 — `backupDb.js:17,89,151`: `BACKUP_KEEP_DAYS` is a file count, not days.**

The variable is used as `backups.slice(keep)`. Rename it to `BACKUP_KEEP_COUNT` (and keep a compatibility alias), or implement age-based pruning from file mtime.

**F-12 — `backupDb.js:51-61`: write-stream completion is not awaited.**

The promise resolves on the child `close` event after `out.end()`, but not after the stream’s `finish` event. The immediate `fs.statSync` at line 146 can race with buffered writes.

**Fix:** await `stream/promises.finished(out)` before resolving.

**F-13 — `matchController.js:1896-1920`: featured-match cap is check-then-save.**

Two concurrent requests can both see `count < FEATURED_MATCH_CAP` and both enable a match. Use an atomic update/transaction or re-check the count after saving.

**F-14 — `tournamentImpact.js:353-377`: MOM-only players can have `matches: 0`.**

`matches` comes from `collectPlayedMatches`, while the MOM bonus can create a row without an appearance. An awarded player can therefore show an award and zero matches. The default fielding weights are all positive, so this is normally display-only; it becomes a real gap only if a caller overrides weights to zero.

**Fix:** decide whether an award implies an appearance; if not, document the display. If zero weights are supported, only set `fieldingRecorded` when a positive fielding weight was applied.

**F-15 — `authMiddleware.js:118-146`: `optionalProtect` bypasses the temporary-password gate.**

`protect` blocks a `mustChangePassword` user from everything except the allowlisted auth paths. `optionalProtect` applies token-version and suspension checks but not `mustChangePassword`. Such a user can still read viewer-dependent public endpoints. Impact is limited because those routes are public, but the gate is not uniform.

**Fix:** either document the intentional difference or apply the same gate before attaching `req.user`.

**F-16 — `setBattingPositions.test.js:141-146`: test depends on ambient `NODE_ENV`.**

`isTestTarget("contest")` defaults to `process.env.NODE_ENV`. With `NODE_ENV=test`, the result is `true` and the test fails; with `NODE_ENV` unset it passes. Pass the environment explicitly in the test.

**F-17 — Deployment and CI hardening.**

`docker-compose.yml` publishes Mongo `27017` when the `local-mongo` profile is active and exposes backend/admin/user ports directly. There is no TLS/reverse proxy or resource limit. CI runs Node 20, starts the backend with a local Mongo service, runs `npm test` then smoke tests, and runs Admin/User component tests plus Vite builds. There is no `continue-on-error`/allow-failure. The backend job is not run against an authenticated Mongo, so F-09 would not be caught.

**Fix:** keep Mongo unpublished outside local development, put TLS/reverse proxy in front of public ports, add resource limits, and add an authenticated-Mongo backup smoke check.
